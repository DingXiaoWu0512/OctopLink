# Feature Specification: 第四批精修+排障（导航栏光感还原/模型配置编辑/渠道品牌Logo/气泡用量归位/操作按钮放大/输入框对齐/新会话按钮对齐/语音识别422修复）

**Created**: 2026-10-29  
**Status**: Approved  
**Input**: User description: "① 导航栏光感恢复（实在解决不了就别让导航栏下沉了，就正常在就行）；② 模型配置点开修改；③ 渠道图片接收不到（渠道品牌照片，如飞书显示飞书 Logo）从客户端拉取；④ 气泡上下文（token 用量）放框内右下角；⑤ 复制/朗读/重试按钮放大 20%、字和底下边框距离缩小 20%；⑥ 输入消息框和导航栏一样宽；⑦ 新会话按钮竖向对齐发送按钮再抬高点；⑧ 语音识别 422 修复"

## Overview

本批为 8 项精修与功能修复：导航栏沉浸光感因第三批自绘导航栏丢失（官方文档确证：沉浸光感仅系统 Navigation 标题栏与横向 Tabs 底部 TabBar 生效，自绘组件无效），需还原系统 Tabs 底部 TabBar 并放弃键盘下沉动画；模型配置页 provider 卡片补点击编辑入口；渠道列表卡片从文字渐变徽章升级为品牌 Logo 图片（客户端本地携带，与 dashboard 同源资源）；聊天气泡 token 用量从气泡外右侧胶囊移入气泡框内右下角；气泡操作按钮放大 20%、文字与底边距离缩小 20%；聊天输入框宽度与导航栏对齐；新会话按钮竖向对齐发送按钮并抬高；修复语音识别 422（根因：multipart 请求头缺少 Content-Type，multiFormDataList 未生效，FastAPI 校验失败——一处修复同时救活全部 multipart 上传链路）。全部为客户端改动，服务器端零改动。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 语音识别恢复正常（422 修复）(Priority: P1)

用户在聊天页点麦克风录音、再点停止后，语音被正常上传识别，识别出的文字追加到输入框；不再出现"请求失败 (422)"错误提示。上传链路修复同时覆盖所有依赖 multipart 上传的功能（头像上传、聊天附件上传、工作区文件上传、技能包上传、语音识别）。

**Why this priority**: 功能性故障修复，语音输入完全不可用；且根因修复使全部 multipart 上传恢复，价值最大。

**Independent Test**: 聊天页录音 2 秒以上→停止→观察无 422 提示且识别文字进入输入框（服务器配置了可用的服务端 STT provider 时）；hilog 确认 POST /api/voice/stt 返回 200。

**Acceptance Scenarios**:

1. **Given** 聊天页（已授权麦克风权限、服务器已配置服务端 STT provider），**When** 点麦克风录音≥2 秒后再次点击停止，**Then** 请求成功（非 422），识别文字追加到输入框。
2. **Given** 录音内容为空（0 字节），**When** 停止录音，**Then** 提示"录音内容为空"，不发请求（客户端拦截保持不变）。
3. **Given** 服务器当前生效的 STT 为浏览器类型（VOICE_BROWSER_ONLY），**When** 上传语音，**Then** 显示服务端语义化错误信息（"语音输入仅在浏览器中可用。"），而非"请求失败 (422)"。
4. **Given** 任意其他 multipart 上传入口（如聊天附件上传），**When** 上传文件，**Then** 请求体被服务器正确解析，不再出现 422。

### User Story 2 - 导航栏光感还原（系统 TabBar）(Priority: P1)

主页底部导航栏还原为系统 Tabs 底部 TabBar：四标签（专家/聊天/工作台/我的）图标+文字、点击切换与当前态高亮保持；TabBar 呈现沉浸光感材质（毛玻璃+高光描边，内容从其后模糊透出），且随"沉浸光感"开关响应；键盘弹出时导航栏不再有下沉/隐藏动画（放弃第三批的键盘下沉设计，导航栏保持正常位置，由系统键盘避让处理）。

**Why this priority**: 用户点名的第一项，光感是用户在真机上明确期望恢复的核心视觉特性；官方文档确证自绘组件无法承载沉浸光感，系统 TabBar 是唯一通道。

**Independent Test**: 部署后查看主页底部导航栏：常态呈材质毛玻璃+高光；聊天列表滚动时内容从导航栏后模糊透出；切换"沉浸光感"开关后导航栏材质响应；点击四标签切换正常。

**Acceptance Scenarios**:

1. **Given** 主页，**When** 查看底部导航栏，**Then** 呈现系统 TabBar 毛玻璃材质+高光描边（沉浸光感），四标签图标文字齐全。
2. **Given** 聊天页有滚动内容，**When** 滚动列表，**Then** 内容从导航栏后方模糊透出（材质透出效果）。
3. **Given** 我的页"沉浸光感"开关，**When** 切换开/关，**Then** 导航栏材质实时响应（开启=材质光感，关闭=普通半透明底）。
4. **Given** 聊天输入框，**When** 唤起输入法，**Then** 导航栏不执行缩放/下沉动画，保持系统默认键盘避让行为；收起键盘后导航栏完整可见。
5. **Given** 四个标签，**When** 依次点击切换，**Then** 页面内容正确切换、当前标签高亮态正确。
6. **Given** 从主页推入的二级页（导航栏被覆盖），**When** 返回主页，**Then** 导航栏状态正常、材质无闪烁。

### User Story 3 - 模型配置可从卡片点击编辑 (Priority: P2)

用户在模型配置页（我的→模型配置）点击任意 provider 卡片即可弹出操作菜单（原来仅长按触发，点击无响应、不可发现），菜单中"编辑"可直接进入编辑表单；编辑入口不再因表单挂载点与菜单关闭的时序冲突而失效。

**Why this priority**: 可发现性缺陷：编辑功能存在但入口不可发现（仅长按），用户点名"点开修改"。

**Independent Test**: 进入模型配置页，单击 provider 卡片→菜单弹出→点"编辑"→编辑表单打开且预填当前配置。

**Acceptance Scenarios**:

1. **Given** 模型配置页 provider 列表，**When** 单击任意 provider 卡片，**Then** 弹出该 provider 的操作菜单（与长按菜单一致）。
2. **Given** 打开的 provider 操作菜单，**When** 点击"编辑"，**Then** 菜单关闭后编辑表单正常打开（不出现菜单与表单互相顶掉的情况）。
3. **Given** 编辑表单，**When** 查看表单字段，**Then** 预填该 provider 当前配置，修改保存后列表回显新值。
4. **Given** 无 providers 管理权限的用户，**When** 查看卡片，**Then** 只读行为保持（点击不出现管理菜单或提示无权限），与现行为一致。

### User Story 4 - 渠道列表显示品牌 Logo (Priority: P2)

用户在工作台→渠道接入查看渠道列表时，每个渠道卡片左侧 44×44 圆角徽章内显示对应平台品牌 Logo 图片（如飞书渠道显示飞书 Logo、钉钉显示钉钉 Logo、企业微信/微信/QQ/元宝同理），替代现在的单字渐变文字徽章；无品牌资源的未知渠道类型回退现有文字徽章，不出现空白。

**Why this priority**: 用户点名的品牌识别需求；dashboard 同源资源已就绪，客户端本地携带即可。

**Independent Test**: 打开渠道页查看已接入渠道（飞书/微信等）卡片，左侧显示对应品牌 Logo 图片；未知 kind 渠道显示文字徽章回退。

**Acceptance Scenarios**:

1. **Given** 渠道页存在飞书渠道，**When** 查看渠道卡片，**Then** 左侧徽章内显示飞书品牌 Logo 图片（非"飞"文字）。
2. **Given** 钉钉/企业微信/微信/QQ/元宝渠道，**When** 查看，**Then** 各自显示对应品牌 Logo。
3. **Given** 插件贡献的未知 kind 渠道（无品牌资源），**When** 查看，**Then** 回退显示现有文字渐变徽章，不空白、不报错。
4. **Given** 停用状态的渠道，**When** 查看，**Then** Logo 徽章保持现有停用降透明度视觉。

### User Story 5 - 气泡上下文用量移入框内右下角 (Priority: P2)

用户查看助手消息时，token 用量（↑输入 ↓输出）从气泡外右侧竖排胶囊移到气泡框内右下角：位于气泡内容底部（操作行所在层次）右对齐，与气泡内其他元素间距协调；无用量数据的消息不显示不占位。

**Why this priority**: 用户点名的信息归位项，上一批放在框外右侧不符合期望。

**Independent Test**: 打开有用量数据的对话，气泡内右下角显示用量，气泡外右侧不再有竖排胶囊。

**Acceptance Scenarios**:

1. **Given** 一条带用量数据的助手消息，**When** 查看气泡，**Then** 用量（↑↓）显示在气泡框内右下角，右对齐。
2. **Given** 气泡外的右侧区域，**When** 查看，**Then** 不再有竖排用量胶囊。
3. **Given** 无用量数据的消息（历史消息无用量），**When** 查看，**Then** 气泡内右下角不显示用量、不占位。
4. **Given** 长文本气泡与短文本气泡，**When** 分别查看，**Then** 用量均贴气泡内右下角，布局不溢出不换行错乱。

### User Story 6 - 操作按钮放大 20%、文字与底边距离缩小 20% (Priority: P3)

助手/用户消息气泡底部操作行的复制/朗读/重试按钮整体放大 20%（按钮容器与图标同比放大），操作行文字/图标与气泡底边的距离缩小 20%，按钮更易点按、底部留白更紧凑。

**Why this priority**: 用户点名的可点按性与紧凑性精修。

**Independent Test**: 对比修改前后的操作行：按钮约放大 20%，底部间距约缩小 20%；点击复制/朗读/重试功能正常。

**Acceptance Scenarios**:

1. **Given** 助手消息气泡操作行，**When** 查看，**Then** 复制/朗读/重试按钮尺寸较此前放大 20%（约 24vp 容器/14vp 图标级别），图标清晰。
2. **Given** 操作行与气泡底边，**When** 测量间距，**Then** 较此前缩小 20%（约 11vp 级别）。
3. **Given** 放大后的三个按钮，**When** 依次点击，**Then** 复制、朗读（三态）、重试功能正常，无 TTS 链路回归。

---

### User Story 7 - 输入框与导航栏同宽 (Priority: P3)

聊天页底部输入卡片（输入框+操作行）的左右边距与底部导航栏内容区对齐，宽度一致，不再一边宽一边窄。

**Why this priority**: 用户点名的对齐精修。

**Independent Test**: 查看聊天页底部：输入卡左右边缘与导航栏（系统 TabBar）内容左右边缘对齐。

**Acceptance Scenarios**:

1. **Given** 聊天页，**When** 查看输入卡片与底部导航栏，**Then** 输入卡左右边距与系统 TabBar 默认内容边距一致（16vp 级别），视觉同宽。
2. **Given** 不同窗口宽度（分屏/折叠等），**When** 查看，**Then** 对齐关系保持，不溢出。

---

### User Story 8 - 新会话按钮竖向对齐发送按钮并抬高 (Priority: P3)

聊天页右上角悬浮的"新会话"按钮（方框铅笔图标）水平位置调整到与底部发送按钮竖向对齐（同一垂直线），并适当抬高（远离输入区），不遮挡消息内容的关键区域。

**Why this priority**: 用户点名的对齐+位置精修。

**Independent Test**: 查看聊天页：新会话按钮与发送按钮中心在同一垂直线上，位置较此前更高。

**Acceptance Scenarios**:

1. **Given** 聊天页，**When** 从发送按钮中心向上作垂线，**Then** 新会话按钮中心基本落在该垂线上（视觉对齐）。
2. **Given** 新会话按钮，**When** 对比此前位置，**Then** 更高（离输入卡更远），不遮挡最后一条消息正文的关键内容。
3. **Given** 新会话按钮，**When** 点击，**Then** 正常触发新会话流程（清空当前会话进入新会话），功能无回归。

### Edge Cases

- 沉浸光感开关关闭或设备不支持沉浸光感时，导航栏降级为普通半透明底+描边，四标签功能不受影响。
- barFloatingStyle 悬浮样式在低版本 API 不可用时的兼容降级（系统 Tabs 普通底部 TabBar）。
- 语音识别在服务器 STT 未配置/浏览器类型/网络失败三种情况下分别给出可理解的提示，不崩溃。
- 品牌 Logo 资源缺失的渠道类型回退文字徽章。
- multipart 修复后，超大文件上传的超时与错误提示保持现有行为（连接 10s/读 120s 超时不变）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 multipart 文件上传请求 MUST 携带 `Content-Type: multipart/form-data` 请求头（multiFormDataList 生效的必要条件），使服务端正确解析文件字段。
- **FR-002**: 主页底部导航栏 MUST 使用系统 Tabs 底部 TabBar（BarPosition.End）承载四标签切换，并通过悬浮样式参数挂载沉浸光感材质（与全局"沉浸光感"开关联动）。
- **FR-003**: 主页 MUST 移除自绘导航栏与键盘下沉动画逻辑（键盘弹出/收起不再对导航栏做变换动画，交由系统键盘避让）。
- **FR-004**: 模型配置页 provider 卡片 MUST 支持单击弹出操作菜单（与长按菜单一致），且菜单"编辑"动作能稳定打开编辑表单。
- **FR-005**: 渠道列表卡片 MUST 按渠道类型显示对应品牌 Logo 图片资源（客户端本地资源），未知类型回退文字徽章。
- **FR-006**: 助手消息气泡的 token 用量 MUST 显示在气泡框内右下角（右对齐），气泡外不再显示用量胶囊；无用量数据不显示。
- **FR-007**: 气泡操作行复制/朗读/重试按钮 MUST 放大 20%，操作行与气泡底边距离 MUST 缩小 20%。
- **FR-008**: 聊天输入卡片左右边距 MUST 与系统 TabBar 内容边距一致（16vp）。
- **FR-009**: 新会话按钮 MUST 与发送按钮竖向对齐并较此前抬高。
- **FR-010**: 上述全部改动 MUST NOT 破坏既有功能：TTS 朗读三态链路、QR 扫码接入、渠道启停/删除、模型选择面板、四标签路由。

### Key Entities

- **MsgAttachmentModel / 聊天消息用量**：消息用量展示位置调整，仅展示层变化，数据字段（输入/输出 token）不变。
- **ChannelModel（渠道）**：kind 字段驱动品牌 Logo 映射（feishu/dingtalk/wecom/weixin/qq/yuanbao/telegram/discord 等已知 kind→品牌资源，其余回退）。
- **VoiceProviderModel / 语音 provider**：卡片点击菜单与编辑表单复用既有模型与服务，无数据结构变化。
- **系统 Tabs TabBar 悬浮样式**：FloatingTabBarStyle（悬浮宽度/底边距/遮罩/系统材质）承载沉浸光感材质，开关状态经全局存储联动。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 录音上传请求在服务器 STT 可用时返回 2xx，识别文字进入输入框；422 消失（hilog 验证）。
- **SC-002**: 全部 5 类 multipart 上传入口（语音/头像/聊天附件/工作区文件/技能包）请求均被服务端正确解析。
- **SC-003**: 主页导航栏在支持设备上呈现沉浸光感材质（毛玻璃+高光），随开关联动；四标签切换与页面路由 100% 正常。
- **SC-004**: 模型配置页单击卡片 100% 弹出菜单，"编辑"100% 打开表单（20 次连续操作无时序失败）。
- **SC-005**: 已知品牌渠道 100% 显示对应 Logo；未知 kind 渠道 100% 回退徽章。
- **SC-006**: 全部 8 项逐条验收通过（本批验收清单 8/8）。

## Assumptions

- 服务器端零改动；服务端源码（本地缓存）仅作契约参考。
- 渠道品牌 Logo 资源取自 dashboard 同源 SVG/PNG（本地缓存已有），复制进应用资源目录；HarmonyOS Image 支持 SVG 媒体资源。
- 用户服务器已配置或将会配置服务端 STT provider（openai/tencent/mimo 类）；若当前生效 STT 为浏览器类型，应用显示服务端语义错误信息（属预期行为，非本缺陷）。
- 沉浸光感在系统 TabBar 上的生效依赖设备算力与系统版本（API 26+ 悬浮样式），不支持时降级为普通 TabBar，不阻塞验收的其余子项。
- 推送验证以模拟器为准（127.0.0.1:5555）；材质光感的最终视觉效果以用户真机复验为准。
- 本批不改动 LocalTtsService/TtsModels/AppPrefs tts_* 等第三批已交付的 TTS 链路文件。
