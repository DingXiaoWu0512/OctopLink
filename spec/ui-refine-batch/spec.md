# Feature Specification: 移动端 UI 精修批次（UI Refine Batch）

**Created**: 2026-10-29
**Status**: Approved（用户明确授权：需求已具体，不再询问，直接执行并逐条验收）
**Input**: 用户批次反馈（[turn_o99287] + [turn_13h9kt]）：气泡设置层缩窄与上下文数字右置、专家页筛选改滑动胶囊、移动端设置模型 API 确认、技能/插件/记忆迁移/接入渠道弹窗布局优化、插件目录页面布局、渠道头像美化、扫码接入二维码修复、专家页滚动底部遮挡修复。

## Overview

对现有页面做一批 UI 精修与缺陷修复，共 8 项：① 输入气泡的设置层（深度思考 pill + 底部工具行设置控件）紧凑收窄，上下文百分比数字固定在气泡右缘近旁（紧贴发送按钮左侧）；② 专家页筛选行（全部/运行中/未运行/全部用户）改为滑动胶囊分段控件，并修复滚动到底时最后一张卡片被悬浮导航栏遮挡的问题；③ 确认移动端设置模型的能力（调研项，已有结论：支持，无需改动）；④ 技能页三个弹窗与插件页安装 sheet/页面布局优化；⑤ 记忆迁移入口弹窗与接入渠道弹窗布局优化；⑥ 渠道列表头像从"字母+纯色"升级为渐变精致样式（服务器 API 不提供渠道头像，已核实）；⑦ 修复所有扫码接入二维码拿不到的问题（相对 URL 未拼接服务器地址、无加载失败处理）；⑧ 全部改动保持现有视觉语言（玻璃材质、圆角、胶囊）与既有功能回归无损。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 输入气泡设置层紧凑化与上下文数字右置 (Priority: P1)

用户在聊天页看到输入气泡的设置层（卡上方"深度思考" pill、卡底部工具行的润色/麦克风/模型 pill）过于占宽、稀疏拉伸；上下文百分比数字应始终位于气泡右缘近旁（紧贴发送按钮左侧），不因左侧控件挤压而偏离。改造后：设置控件尺寸与间距紧凑收窄、整体不再稀疏，上下文百分比 pill 固定锚定在发送按钮左侧。

**Why this priority**: 聊天输入区是最高频使用界面，窄屏（真机 ~440vp 窗口）下工具行溢出挤压导致上下文数字位置漂移。

**Independent Test**: 聊天页（键盘态）截图核对工具行紧凑度与上下文 % pill 位置（发送按钮左侧紧贴）。

**Acceptance Scenarios**:

1. **Given** 聊天页输入气泡, **When** 渲染工具行, **Then** 附件/润色/麦克风按钮与模型 pill 尺寸、间距紧凑，无稀疏拉伸感
2. **Given** 有活跃线程（contextUsage 非 null）, **When** 工具行渲染, **Then** 上下文百分比 pill 位于发送按钮左侧、间距 ≤6vp，即气泡右缘近旁
3. **Given** 深度思考 pill 可见, **When** 渲染, **Then** pill 尺寸紧凑，与输入卡整体视觉协调
4. **Given** 任意改动, **When** 附件上传/润色/麦克风/模型选择/发送/上下文详情各功能操作, **Then** 全部正常（回归无损）

### User Story 2 - 专家页滑动胶囊筛选与底部遮挡修复 (Priority: P1)

专家页标题栏底部筛选行（全部/运行中/未运行/全部用户[管理员]）从独立 chips 改为**滑动胶囊**分段控件：选项置于一个胶囊容器内，选中项带滑块高亮并随切换平滑滑动。同时修复：列表滚动到底时最后一张专家卡被底部悬浮导航栏遮挡——增加底部占位使最后一张卡片完整停在导航栏上方。

**Why this priority**: 筛选行是专家页核心交互；底部遮挡导致最后一张卡片部分不可用，属功能缺陷。

**Independent Test**: 专家页点击各筛选段验证滑动高亮与列表过滤；滚动到底验证最后一张卡片完整可见、停在悬浮导航栏上方。

**Acceptance Scenarios**:

1. **Given** 专家页, **When** 页面加载, **Then** 筛选行呈胶囊分段容器，当前筛选段高亮
2. **Given** 筛选胶囊, **When** 点击其他段, **Then** 高亮滑块平滑滑动到新段，列表按新条件过滤（数据逻辑不变：mine/all scope、running 状态过滤）
3. **Given** 管理员账号, **When** 查看筛选, **Then** 包含"全部用户"段；普通用户不含
4. **Given** 专家列表, **When** 滚动到底, **Then** 最后一张卡片下边缘完整显示在悬浮导航栏上方，无遮挡、可正常点击
5. **Given** 搜索态, **When** 输入关键词, **Then** 搜索框替换筛选行（既有行为不变）

---

### User Story 3 - 扫码接入二维码修复 (Priority: P1)

所有扫码接入（钉钉/企微/QQ/微信/飞书/元宝）的二维码当前拿不到（Image 静默加载失败或无限转圈）。修复：qrcode_url 为相对路径时拼接服务器 baseUrl（含鉴权参数，参照 MeTab.avatarFullUrl 的既有模式）；Image 增加加载失败处理——显示明确失败态与重试入口；generate 接口失败不再停留在无提示的 Loading 态。

**Why this priority**: 扫码接入功能当前完全不可用，属阻断级缺陷。

**Independent Test**: 渠道页 → 接入渠道 → 扫码接入：选择平台后二维码可加载显示（服务器返回 qrcode_url 时）；加载失败时显示失败态+重试，不再无限转圈。

**Acceptance Scenarios**:

1. **Given** 扫码 sheet, **When** 服务器返回相对 qrcode_url, **Then** Image 加载完整 URL（含鉴权），二维码正常显示
2. **Given** 扫码 sheet, **When** 二维码加载失败, **Then** 显示失败提示与重试按钮，不无限转圈
3. **Given** generate 接口失败, **When** 返回错误, **Then** sheet 显示错误文案与重试，不停留在纯 Loading 态
4. **Given** 轮询进行中, **When** 二维码已显示, **Then** 轮询/状态文字/验证码展示行为保持（回归无损）

### User Story 4 - 技能与插件弹窗/页面布局优化 (Priority: P2)

技能页三个弹窗（新建/编辑/导入）与插件页安装 sheet（插件市场/通过 URL 安装/工具配置）及插件页主体布局优化：统一弹窗版式（标题层级、内容区可滚动、输入控件规格、操作按钮高度与排布、间距节奏），消除拥挤与不一致。

**Why this priority**: 弹窗是技能/插件管理的核心操作界面，当前版式拥挤不一致影响可用性与观感。

**Independent Test**: 打开新建技能/编辑技能/导入技能弹窗与插件安装各 sheet、插件页主体，核对版式统一、间距合理、内容可滚动、按钮可达。

**Acceptance Scenarios**:

1. **Given** 技能页, **When** 打开新建/编辑/导入弹窗, **Then** 版式统一：标题、输入控件、开关行、取消/主按钮排布一致，内容超高可滚动
2. **Given** 插件页, **When** 打开插件市场/URL 安装/工具配置 sheet, **Then** 列表行、安装按钮、输入区布局整齐，间距一致
3. **Given** 插件页主体, **When** 浏览全局插件/此专家插件, **Then** 分区标题、列表行、开关布局优化，视觉层次清晰
4. **Given** 任意弹窗操作, **When** 创建/编辑/导入/安装/启停/卸载, **Then** 功能全部正常（回归无损）

---

### User Story 5 - 记忆迁移与接入渠道弹窗布局优化 (Priority: P2)

记忆迁移入口（当前为 ActionSheet：导出记忆包/导入记忆包）升级为布局精致的选择弹窗：两个选项行带图标与说明文字；接入渠道弹窗（创建渠道/扫码接入双卡）优化布局。导出/导入 .hmpkg 逻辑与创建/扫码流程保持不变。

**Why this priority**: 两处弹窗为记忆与渠道接入的关键入口，当前版式简陋。

**Independent Test**: 记忆页点迁移按钮 → 新版选择弹窗两个选项可选并分别触发导出/导入；渠道页点 + → 接入渠道双卡布局整齐、两个入口可达。

**Acceptance Scenarios**:

1. **Given** 记忆页, **When** 点击迁移按钮, **Then** 弹出新版选择弹窗：导出记忆包/导入记忆包两个选项行（图标+标题+说明），布局精致
2. **Given** 迁移弹窗, **When** 选择导出/导入, **Then** 分别走既有 exportPackage/importPackage 流程（回归无损）
3. **Given** 渠道页, **When** 点击 + 打开接入渠道, **Then** 创建渠道/扫码接入双卡布局优化：图标、标题、说明、间距整齐，两入口可达
4. **Given** 接入渠道, **When** 分别进入创建/扫码, **Then** 后续流程不变（回归无损）

---

### User Story 6 - 渠道头像美化 (Priority: P2)

渠道列表头像从"单字母+纯色方块"升级为精致渐变样式：平台品牌色渐变背景、更优的排版层次、柔和描边与圆角，禁用态保持半透明。服务器 API 已核实不提供渠道头像字段（ChannelModel 仅 id/kind/name/enabled/runtime），故以高质量占位样式呈现。

**Why this priority**: 渠道列表是渠道管理主界面，头像观感直接影响品质感。

**Independent Test**: 渠道页列表截图核对头像渐变样式与整体协调性。

**Acceptance Scenarios**:

1. **Given** 渠道列表, **When** 渲染列表项, **Then** 头像为平台品牌色渐变背景+字母的精致样式，非纯色平涂
2. **Given** 各平台渠道（钉钉/企微/QQ/微信/飞书/元宝/插件类型）, **When** 渲染头像, **Then** 各平台品牌色区分明显，未知类型有优雅回退
3. **Given** 禁用渠道, **When** 渲染头像, **Then** 保持半透明禁用态（回归无损）

### Edge Cases

- 窄屏（~320vp 输入卡宽）下工具行不溢出、上下文 pill 不被挤压消失
- 专家列表为空/筛选无结果时，滑动胶囊与空态展示正常
- 管理员与非管理员筛选段数量切换时滑块位置正确
- 扫码 generate 返回仅 token 无 qrcode_url：显示验证码文字态而非无限转圈
- 插件/技能弹窗内容超高（长文本/SKILL.md）：可滚动且底部按钮不被键盘遮挡
- 渠道 kind 为插件贡献类型：头像回退样式正常

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 输入气泡工具行（附件/润色/麦克风/模型 pill）与深度思考 pill MUST 尺寸与间距紧凑收窄，消除稀疏拉伸
- **FR-002**: 上下文百分比 pill MUST 固定位于发送按钮左侧（间距 ≤6vp），即气泡右缘近旁，不因左侧内容挤压而偏离或消失
- **FR-003**: 专家页筛选行 MUST 改为滑动胶囊分段控件（胶囊容器+选中滑块平滑滑动），数据过滤逻辑（scope mine/all、running 状态、管理员"全部用户"段）保持不变
- **FR-004**: 专家页列表 MUST 增加底部占位（高度 = MainPage 传入的 bottomPad，当前该 prop 未被使用），使最后一张卡片完整停在悬浮导航栏上方
- **FR-005**: 扫码接入 qrcode_url 为相对路径时 MUST 拼接服务器 baseUrl 并携带鉴权参数（参照 MeTab.avatarFullUrl 既有模式），二维码正常加载
- **FR-006**: 二维码加载失败/generate 失败 MUST 显示明确失败态与重试入口，MUST NOT 无限转圈或静默无提示
- **FR-007**: 技能页新建/编辑/导入弹窗与插件页市场/URL 安装/工具配置 sheet MUST 版式统一（标题层级、内容可滚动、输入控件规格、按钮排布与高度一致）
- **FR-008**: 插件页主体（全局插件/此专家插件分区）MUST 布局优化：分区标题、列表行、开关视觉层次清晰
- **FR-009**: 记忆迁移入口 MUST 升级为带图标与说明的双选项选择弹窗，导出/导入流程不变
- **FR-010**: 接入渠道弹窗（创建渠道/扫码接入双卡）MUST 布局优化，两入口可达且流程不变
- **FR-011**: 渠道列表头像 MUST 升级为平台品牌色渐变样式（含未知类型回退与禁用态半透明）
- **FR-012**: 所有改动 MUST 保持既有功能回归无损（附件/润色/麦克风/模型选择/发送/上下文详情/专家筛选与搜索/技能创建导入/插件安装启停卸载/记忆导出导入/渠道创建扫码测试启停删除）
- **FR-013**（调研结论，无代码改动）: 移动端设置模型能力确认——支持，共三条路径：① 会话级持久化（ThreadSettingsPage → PATCH /api/agents/{id}/threads/{tid}，model_ref/reasoning_mode/reasoning_effort）；② 逐轮模型（输入卡模型 pill → WS user_turn 帧 model 字段，不落库）；③ 专家级默认模型（创建/编辑专家 default_model）。模型列表来自 GET /api/providers/resolved（ModelPickerSheet）。

### Key Entities *(include if feature involves data)*

- **专家筛选段（ExpertFilterOption）**: 既有实体（label/value），渲染方式由 chips 改为滑动胶囊段
- **二维码会话（QrSessionModel）**: 既有实体（token/qrcodeUrl/userCode），新增"完整可加载 URL"派生值（baseUrl 拼接+鉴权）与加载状态（loading/loaded/failed）
- **平台徽标（platformBadge）**: 既有映射（kind→label/color），扩展为 kind→label/渐变色对/文字色
- **输入卡工具行**: 既有控件群，仅尺寸/间距/排布调整，无新增实体

## Assumptions

- 用户已明确授权：跳过所有澄清与确认询问，直接执行并在完成后逐条验收
- 服务器端零改动：渠道头像走高质量占位（API 无头像字段，已核实 ChannelModel 仅五字段）；二维码修复为端侧 URL 拼接
- "滑动胶囊"理解为胶囊容器+选中滑块平滑滑动的分段控件；如实现层发现更贴近系统规范的等价组件（如 Hds 组件库既有分段胶囊）可替代，以观感一致为准
- 弹窗"优化布局"以统一版式标准执行：与项目最佳实践弹窗（如语音设置 preset 弹窗）对齐——标题/内容/按钮层级、40 高主按钮、内容可滚动
- 全部改动沿用现有视觉语言：玻璃材质（UiMaterialKit）、24 圆角卡片、胶囊按钮、中文文案
- message-tts 批次（已实施待验证）与本批次互不干扰：TTS 改动文件（MessageBubble 朗读链路、VoiceSettingsPage、LocalTtsService 系）本批次不触碰
