# Feature Specification: UI 精修第三批（弹窗统一/模型配置/气泡精修/键盘避让/我的页增强）

**Created**: 2026-10-29  
**Status**: Approved  
**Input**: User description: "① 全部列表选择弹窗统一为记忆迁移弹窗样式；② 移动端模型配置（加页面）；③ 聊天气泡底部操作行（复制/朗读/重发）变窄去横线；④ token 用量显示在气泡右侧（优化数字或胶囊）；⑤ 输入法弹出时导航栏用缩放动画隐藏在输入法下面，输入法收起时缩放回来，节省输入时空间；⑥ 我的页面账号下面增加一列：使用说明、反馈与建议、关于；⑦ 我的外观选项做成滑动胶囊形式；⑧ 沉浸光感开关状态太单调，需要优化；⑨ 修复获取平台二维码直接收不到的问题"

## Overview

本批为 9 项 UI/UX 精修与修复需求：把全应用 24 处系统列表选择弹窗统一为"记忆迁移弹窗"半模态样式；新增移动端模型配置页（承接服务层已就绪但零 UI 的 provider 管理能力）；精修聊天气泡（操作行变窄去横线、token 用量移到气泡右侧胶囊）；键盘弹出时底部导航栏缩放动画隐藏以释放输入空间；我的页新增"使用说明/反馈与建议/关于"三个支持入口；外观选项改滑动胶囊；沉浸光感开关状态展示优化；修复渠道扫码接入时平台二维码收不到的功能故障。除 QR 修复涉及对服务端返回字段语义的正确适配（服务器零改动）外，全部为客户端改动。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 全部列表选择弹窗统一为记忆迁移弹窗样式 (Priority: P1)

用户在任何页面触发"列表选择菜单"（长按列表项操作菜单、添加方式选择、导出格式选择、批量操作选择、角色选择等 25 处），弹出的不再是系统 ActionSheet，而是与"记忆迁移弹窗"一致的半模态样式：顶部标题+副题，下方每个选项一行（44×44 圆角图标容器 + 选项标题 + 可选说明文字），整行可点，点击后关闭面板并执行动作；危险操作（删除类）图标与文字呈红色警示态。

**Why this priority**: 用户点名的第一批需求，涉及全应用 25 处交互入口，是本批最大范围的统一性改造。

**Independent Test**: 逐处触发 25 个菜单（长按/点击入口），验证每个菜单均呈现新样式且每个选项动作仍正确执行。

**Acceptance Scenarios**:

1. **Given** 任意含长按菜单的页面（如会话列表、专家列表、渠道页），**When** 长按列表项，**Then** 弹出半模态面板：标题为项名称、选项行为"图标容器+标题+说明"整行可点样式，无系统 ActionSheet 出现。
2. **Given** 打开的菜单面板，**When** 点击任一选项行，**Then** 面板关闭并执行对应动作（如删除弹确认、跳转编辑）。
3. **Given** 菜单中含删除类危险操作，**When** 面板展示，**Then** 该行图标容器背景与文字呈红色警示配色。
4. **Given** 动态选项菜单（如管理员修改用户角色），**When** 打开，**Then** 角色列表按新样式逐行展示且选择生效。
5. **Given** 原系统 ActionSheet 的取消能力，**When** 用户想放弃操作，**Then** 可通过面板关闭按钮/下拉关闭/点击遮罩取消，不执行任何动作。

### User Story 2 - 移动端模型配置页 (Priority: P1)

用户在"我的"页账号节看到"模型配置"入口，进入新页面查看与管理模型：顶部"全局默认模型"卡片显示当前默认模型并支持点击切换（复用模型选择面板）；下方 provider 列表逐卡展示（名称、启停状态、模型数、是否配置密钥），每卡支持长按/点击操作：启用/停用、测试连通、拉取模型列表、编辑、删除；具备 providers 权限的用户还可从预设模板新建 provider（表单填写+草稿试连）。无 providers 权限的用户进入页面仅见全局默认模型卡与只读 provider 状态，管理操作隐藏或提示无权限。

**Why this priority**: 用户点名的第二批核心需求，服务层 API 全部现成但零 UI，是纯新增页面工作，价值密度高。

**Independent Test**: 从我的页进入模型配置页，验证全局默认模型切换、provider 启停/删除/测试/拉取模型、新建 provider 全流程可用。

**Acceptance Scenarios**:

1. **Given** 我的页账号节，**When** 查看，**Then** 存在"模型配置"入口行，点击进入模型配置页。
2. **Given** 模型配置页，**When** 页面加载，**Then** 顶部显示全局默认模型卡（当前 provider/model），下方显示 provider 列表（名称/状态/模型数）。
3. **Given** 全局默认模型卡，**When** 点击，**Then** 弹出模型选择面板，选择后全局默认模型更新并回显。
4. **Given** 某停用的 provider，**When** 执行启用操作，**Then** 列表状态刷新为已启用。
5. **Given** 某 provider，**When** 执行测试连通，**Then** 显示测试成功/失败结果提示。
6. **Given** 具备 providers 权限的用户，**When** 进入页面，**Then** 可新建 provider（选预设模板→填表单→试连→保存成功后列表出现）。
7. **Given** 无 providers 权限的用户，**When** 进入页面，**Then** 仅显示只读信息，管理操作不可见或操作时提示无权限。

### User Story 3 - 聊天气泡底部操作行变窄去横线 (Priority: P2)

用户查看助手/用户消息气泡时，正文与底部操作行之间不再有横线分隔线；操作行（复制/朗读/重发，用户侧仅复制）整体视觉变窄（按钮与间距收紧约三分之一）；操作行与正文的间距和与气泡底边的间距对称一致，整体更轻量不抢正文视觉。

**Why this priority**: 用户点名的视觉精修项，改动小、见效直接。

**Independent Test**: 打开聊天页查看任意已完成回复的气泡，验证无分隔线、按钮行变窄、间距对称。

**Acceptance Scenarios**:

1. **Given** 一条已完成流式的助手消息，**When** 查看气泡，**Then** 正文与操作行之间无任何分隔线，操作行呈现 收缩后的按钮尺寸与间距。
2. **Given** 助手气泡操作行，**When** 对比操作行与正文的间距和与气泡底边的间距，**Then** 两者相等。
3. **Given** 一条用户消息气泡，**When** 查看，**Then** 原半透明分隔线移除，仅剩收紧后的复制入口。
4. **Given** 操作行的复制/朗读/重发按钮，**When** 点击，**Then** 三个动作均正常执行（含朗读三态：合成中/播放中/空闲），本批改动不破坏 TTS 链路。

### User Story 4 - Token 用量显示在气泡右侧 (Priority: P2)

用户查看助手消息时，token 用量（↑输入 ↓输出）不再出现在底部操作行内，而是以紧凑胶囊形式显示在气泡右侧（气泡外、与气泡垂直对齐的小胶囊/小字），仅当该消息有用量数据（大于 0）时显示；无数据的历史消息不占位。

**Why this priority**: 用户点名的信息架构调整，数据链路已闭环，仅调整展示位置与形式。

**Independent Test**: 发送一轮对话收到回复，验证回复气泡右侧出现用量胶囊；翻看历史消息验证有用量的显示、无数据的不显示。

**Acceptance Scenarios**:

1. **Given** 一轮新对话完成（服务器下发用量），**When** 查看该助手气泡，**Then** 气泡右侧显示紧凑用量标识（↑输入数 ↓输出数），操作行内不再有用量文字。
2. **Given** 历史加载的助手消息带用量数据，**When** 查看列表，**Then** 对应气泡右侧同样显示用量标识。
3. **Given** 无用量数据的消息（用量为 0），**When** 查看，**Then** 气泡右侧不显示任何用量占位。
4. **Given** 气泡列表在窄屏滚动，**When** 查看气泡与右侧用量标识，**Then** 布局不溢出、不遮挡相邻消息、滚动跟随正常。

### User Story 5 - 键盘弹出时导航栏缩放隐藏 (Priority: P2)

用户在主页四个标签内的任何输入框唤起输入法时，底部悬浮导航栏以缩放动画（缩小+下移+淡出）隐藏到输入法下方，页面内容不再为导航栏预留空间（输入区直接贴近键盘，腾出约一条导航栏高度的输入视野）；输入法收起时导航栏以缩放动画恢复原位，内容预留同步恢复。导航页（二级页）内的键盘弹出不触发该动画（导航栏本就不可见）。

**Why this priority**: 用户在输入场景下的空间效率需求，涉及主页结构改造，收益明确。

**Independent Test**: 在聊天输入框唤起/收起键盘，观察导航栏缩放隐藏/恢复动画与内容空间变化；在专家列表搜索框验证同样行为。

**Acceptance Scenarios**:

1. **Given** 主页聊天标签，**When** 点击输入框唤起输入法，**Then** 底部导航栏以缩放动画隐藏至键盘下方（约 250ms 级动画，非瞬间消失），内容底部预留同步收紧。
2. **Given** 输入法已弹出、导航栏已隐藏，**When** 收起输入法，**Then** 导航栏以缩放动画恢复显示，内容底部预留恢复。
3. **Given** 主页其他标签的输入场景（专家列表搜索等），**When** 唤起键盘，**Then** 导航栏同样缩放隐藏。
4. **Given** 从主页推入的二级页（导航栏被覆盖不可见），**When** 在二级页内唤起/收起键盘，**Then** 返回主页时导航栏状态与键盘状态一致（键盘已收则导航栏已恢复）。
5. **Given** 键盘弹出状态下切换标签，**When** 查看导航栏，**Then** 保持隐藏，不闪烁恢复。

### User Story 6 - 我的页"支持"入口组：使用说明 / 反馈与建议 / 关于 (Priority: P3)

用户在我的页账号节下方看到新增的一组入口（使用说明、反馈与建议、关于）：使用说明进入内置说明页（分节介绍登录连接、聊天、专家、工作台等功能用法）；反馈与建议弹出半模态反馈面板（反馈说明+一键复制包含版本信息的反馈模板，便于用户通过既有渠道发送）；关于进入关于页（应用标识、口号、动态版本号）。

**Why this priority**: 完善应用支持体系，用户点名新增的三个入口。

**Independent Test**: 我的页依次打开三个入口，验证页面/面板内容完整、返回正常、版本号真实。

**Acceptance Scenarios**:

1. **Given** 我的页，**When** 查看账号节下方，**Then** 出现新入口组：使用说明、反馈与建议、关于，样式与既有节卡片一致。
2. **Given** 点击"使用说明"，**When** 进入说明页，**Then** 分节展示应用主要功能用法说明，可滚动阅读并返回。
3. **Given** 点击"反馈与建议"，**When** 面板弹出，**Then** 显示反馈说明与"复制反馈信息"操作，复制后粘贴板内容包含应用版本等信息。
4. **Given** 点击"关于"，**When** 进入关于页，**Then** 显示应用图标、名称、口号与真实版本号（与应用包版本一致，非硬编码）。
5. **Given** 我的页底部版本文字，**When** 查看，**Then** 与关于页版本号同源一致。

### User Story 7 - 外观选项改为滑动胶囊 (Priority: P3)

用户在我的页外观节看到"浅色/深色/跟随系统"由三个独立按钮胶囊改为单条滑动胶囊分段控件（复用既有滑动胶囊组件样式：选中段随点击平滑滑动），点击任一段立即切换深浅色模式；外观节整体包进与连接/账号节一致的玻璃卡片容器，视觉统一。

**Why this priority**: 用户点名的视觉统一项，组件已存在可直接复用。

**Independent Test**: 我的页外观节切换三个模式，验证滑块动画、模式即时生效、卡片样式一致。

**Acceptance Scenarios**:

1. **Given** 我的外观节，**When** 查看，**Then** 浅色/深色/跟随系统为单条滑动胶囊分段控件，当前模式对应段为选中态。
2. **Given** 滑动胶囊，**When** 点击"深色"，**Then** 滑块动画滑至深色段，应用立即切换深色模式。
3. **Given** 重启应用，**When** 查看外观节，**Then** 选中段与持久化的模式一致。
4. **Given** 外观节整体，**When** 与连接节/账号节对比，**Then** 三者卡片容器样式一致（圆角玻璃卡片+描边）。

### User Story 8 - 沉浸光感开关状态展示优化 (Priority: P3)

用户在我的页查看"沉浸光感"开关时，不再是一个孤零零的 Toggle：行内呈现图标+标题+功能说明副标题（解释该开关控制什么），右侧有当前状态的可视化标识（开启/关闭状态徽标或文字），开关本体带材质光感，开与关呈现明显不同的视觉状态；该行与外观节卡片融为一体。

**Why this priority**: 用户点名的状态可视化优化，完成我的页视觉收尾。

**Independent Test**: 切换沉浸光感开关，验证说明副标题、状态标识随开关变化，材质效果随开关启停。

**Acceptance Scenarios**:

1. **Given** 我的页外观节，**When** 查看沉浸光感行，**Then** 行内含图标、标题、功能说明副标题，右侧显示当前状态标识与开关。
2. **Given** 沉浸光感当前开启，**When** 关闭开关，**Then** 状态标识即时变为关闭态，全应用材质光感效果降级（标题栏渐变模糊等按既有链路关闭）。
3. **Given** 沉浸光感当前关闭，**When** 重新开启，**Then** 状态标识恢复开启态，材质效果恢复。
4. **Given** 重启应用，**When** 查看开关，**Then** 状态与持久化设置一致。

---

### User Story 9 - 修复平台二维码收不到 (Priority: P1)

用户在渠道页通过"接入渠道→扫码接入"选择平台（钉钉/企业微信/微信/QQ）时，页面不再出现"二维码加载失败，请重试"或永久停留在"正在等待平台返回二维码"，而是正确显示平台授权二维码：钉钉/微信/QQ 显示各自平台的登录/授权二维码，企业微信显示授权页二维码并进入短码轮询；扫码轮询确认流程（等待/过期/失败/成功）保持既有状态机行为。

**Why this priority**: 功能性故障（用户无法完成扫码接入渠道），优先级高于纯视觉精修项。

**Independent Test**: 渠道页依次选择四个平台，验证四个平台都能显示二维码并进入轮询等待。

**Acceptance Scenarios**:

1. **Given** 渠道页扫码接入，**When** 选择钉钉，**Then** 显示钉钉授权二维码（客户端将服务端返回的授权链接本地编码为二维码），进入轮询等待。
2. **Given** 扫码接入，**When** 选择企业微信，**Then** 显示企微授权二维码（此前永久等待二维码，修复后正常出码）并按短码轮询。
3. **Given** 扫码接入，**When** 选择微信或 QQ，**Then** 显示对应平台登录二维码。
4. **Given** 二维码显示后，**When** 平台侧确认/超时/失败，**Then** 状态机按既有轮询逻辑流转（成功提示/过期可重试/失败提示）。
5. **Given** 二维码展示区，**When** 在深浅色模式下查看，**Then** 二维码均为深色码点浅色底、清晰可扫描。

---

### Edge Cases

- 25 处菜单中含动态选项菜单（角色列表、批量操作），统一组件必须支持运行时构造选项数组，选项数量 2~6 不等。
- 菜单改半模态后，同一页面可能同时存在多个 bindSheet（表单 sheet+菜单 sheet）：需保证互斥/复用不冲突（同一时刻只开一个）。
- 模型配置页 API 失败（403/网络断开）：列表区域显示错误占位与重试，不崩溃；active-model 切换失败提示并回显旧值。
- 删除 provider 是破坏性操作：必须先弹二次确认。
- token 胶囊在深色/浅色模式下均可读（用主题色资源而非硬编码）。
- 键盘监听回调返回像素高度，需按屏幕密度换算；快速连续唤起/收起键盘时动画不卡死（状态以最终值收敛）。
- 使用说明页内容为静态中文文案，不依赖网络。
- 关于页版本号获取失败时回退到应用包配置的静态版本文本，不显示空白。
- 企业微信平台响应不含独立二维码链接字段（以授权链接字段返回）：二维码内容解析链必须兜底读取该字段。
- 二维码内容为空：不渲染二维码，给出失败提示与重试入口。
- 轮询过期后重试：重新发起扫码后状态机复位，不残留旧状态。

## Requirements *(mandatory)*

### Functional Requirements

**A. 弹窗统一（User Story 1）**

- **FR-001**: 系统必须将全应用 25 处系统列表选择弹窗（ActionSheet）全部替换为统一的半模态面板样式：标题+副题区、选项行（44×44 圆角图标容器+选项标题+可选说明）、整行可点、FIT_CONTENT 半模态、系统材质。
- **FR-002**: 统一面板必须支持危险操作态：指定选项的图标容器背景与文字使用警示红色配色。
- **FR-003**: 统一面板必须支持动态选项（运行时构造的选项数组，含图标/标题/说明/危险标记/回调）。
- **FR-004**: 面板必须支持用户取消（关闭按钮/下拉/遮罩），取消不触发任何动作。
- **FR-005**: 全部 25 处替换后，各菜单的原有动作（跳转/弹确认/调接口/开关切换等）必须保持等价。

**B. 模型配置页（User Story 2）**

- **FR-006**: 我的页账号节必须新增"模型配置"入口，进入新的模型配置页。
- **FR-007**: 模型配置页必须显示全局默认模型卡，支持点击切换全局默认模型（复用既有模型选择面板）。
- **FR-008**: 模型配置页必须显示 provider 列表（名称、启停状态、模型数），支持启用/停用、删除（二次确认）、测试连通（结果提示）、拉取模型列表（结果展示）。
- **FR-009**: 具备 providers 权限的用户必须可以从预设模板新建 provider（预设选择+表单+草稿试连+保存）并编辑既有 provider。
- **FR-010**: 无 providers 权限的用户必须获得只读降级视图，管理操作不可见或操作时提示无权限。
- **FR-011**: 模型配置页所有 API 失败场景必须呈现错误占位/提示与重试，不崩溃。

**C. 气泡精修（User Story 3、4）**

- **FR-012**: 助手气泡正文与操作行之间的分隔线必须移除；用户气泡的半透明分隔线必须移除。
- **FR-013**: 操作行必须整体视觉变窄：按钮尺寸与间距收紧（约缩小三分之一），操作行与正文间距等于与气泡底边间距。
- **FR-014**: 复制/朗读/重发动作必须保持等价，朗读三态（合成中/播放中/空闲）与既有 TTS 链路不被破坏。
- **FR-015**: token 用量必须从操作行移除，改为气泡右侧紧凑标识（胶囊/小字），仅当用量大于 0 时显示。
- **FR-016**: 用量标识必须同时覆盖实时对话（流式用量事件）与历史消息（历史用量字段）两条数据路径，深浅色模式均可读。

**D. 键盘避让导航栏（User Story 5）**

- **FR-017**: 主页底部导航栏必须改为可动画控制的自绘悬浮栏（替换系统悬浮 TabBar 样式），保留四个标签项外观、切换、红点角标能力。
- **FR-018**: 输入法弹出时导航栏必须以缩放动画隐藏至输入法下方（缩小+下移+淡出），输入法收起时以缩放动画恢复。
- **FR-019**: 导航栏隐藏/恢复时，主页各标签的内容底部预留必须同步收紧/恢复（通过既有底部留白传导链路）。
- **FR-020**: 二级页内键盘弹出不触发可见的导航栏动画；返回主页时导航栏状态与键盘状态自动一致。

**E. 我的页支持入口（User Story 6）**

- **FR-021**: 我的页账号节下方必须新增入口组：使用说明、反馈与建议、关于。
- **FR-022**: 使用说明必须为内置静态说明页，分节介绍主要功能用法，无需网络。
- **FR-023**: 反馈与建议必须弹出半模态面板：反馈说明+"复制反馈信息"（粘贴板内容含应用版本信息）。
- **FR-024**: 关于页必须显示应用标识、口号与动态版本号（读应用包真实版本），我的页底部版本文字与之同源。

**F. 外观胶囊与沉浸光感（User Story 7、8）**

- **FR-025**: 外观浅色/深色/跟随系统必须改为单条滑动胶囊分段控件（复用既有滑动胶囊组件），选中段动画滑动，模式即时生效并持久化。
- **FR-026**: 外观节必须包进与连接/账号节一致的玻璃卡片容器。
- **FR-027**: 沉浸光感行必须呈现：图标+标题+功能说明副标题+状态标识+开关；开关状态变化时状态标识即时更新，材质效果按既有链路启停。

**H. 渠道二维码修复（User Story 9）**

- **FR-028**: 平台二维码必须在客户端本地编码渲染（将服务端返回的授权链接字符串编码为二维码图），不得将其作为远程图片 URL 下载。
- **FR-029**: 二维码内容字段解析必须兼容各平台返回差异（含企业微信以授权链接字段返回的场景），四平台（钉钉/企业微信/微信/QQ）全部正常出码。
- **FR-030**: 扫码轮询状态机（等待/过期/失败/成功）既有行为必须保持，修复不得影响接入确认流程。
- **FR-031**: 二维码展示必须保证可扫描性（深色码点浅色底、尺寸充足），深浅色模式均正常。

### Key Entities

- **统一菜单面板（MenuSheet）**: 标题、副题、选项列表（图标、标题、说明、危险标记、点击回调）；由各页面在触发时构造。
- **模型配置页（ProvidersPage）**: 全局默认模型（provider 名+模型名）、provider 卡（名称、启停状态、模型数、密钥配置标记、权限可用操作集）。
- **provider 编辑表单**: 预设模板、名称、接口地址、密钥、模型列表、启用标记等字段（以既有 provider 数据模型为准）。
- **气泡用量标识**: 输入 token 数、输出 token 数；来源为消息模型用量字段的既有路径。
- **导航栏键盘状态**: 键盘可见性（由窗口键盘高度事件推导）、导航栏显隐动画状态、内容底部留白值。
- **扫码会话（QrSession）**: 既有模型补齐授权链接字段的兼容解析（企业微信场景）；二维码渲染内容 = 服务端返回的平台授权链接字符串，由客户端本地编码为二维码。
